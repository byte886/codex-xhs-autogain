# Quality Gates — 质量关卡配置

> 生成自 clean-code-gauntlet 模板。这些关卡是**机器强制**的：Agent 产出的代码必须全部通过才能交接；CI 再跑一遍兜底。

## 两层结构（工具-语言解耦）

| 文件 | 作用 | 语言相关性 |
|------|------|-----------|
| `gates.yaml` | 声明"查什么 + 阈值"（圈复杂度/CRAP/覆盖率/变异/架构） | 语言无关 |
| `tools/<语言>.yaml` | 每个维度对应的实际工具/安装命令/检查命令 | 按语言一份 |

> 规则：**换语言不换关卡**——同一套阈值用四套工具兑现；工具命令变化只改 `tools/<语言>.yaml` 一处。

## 本项目实际使用的工具（由生成器注入）

- 见 `tools/<language>.yaml`（本目录内已生成的那份即当前语言的映射表）。

## 阈值约定（gates.yaml 的镜像，默认）

- **圈复杂度**：≤8（Bob 对 Agent 的放宽阈值；人类标准 ≤4）；
- **CRAP 分**：≥30 视为高风险，必须重构或补测试；
- **覆盖率**：核心模块 ≥80%，其余 ≥60%（项目可按实际调整）；
- **变异测试**：存活变异体 = 0 才允许交接；
- **架构**：依赖方向只允许高层→低层；循环依赖 = 0。

## 关卡脚本（CI 用）

- `ci.yml`：GitHub Actions 模板，命令已按当前语言注入；
- 本地入口：`tooling/bin/install-tools.sh` 安装上游工具后，按 `tools/<语言>.yaml` 的 `<维度>_cmd` 运行。

## 修改纪律

- 阈值/命令修改必须同步：`gates.yaml` + `tools/<语言>.yaml` + constitution/engineering.prompt + 本 README；
- 上游工具命令变化（见 tooling/upstream/*.md 版本卡）→ 更新对应 `tools/<语言>.yaml`。

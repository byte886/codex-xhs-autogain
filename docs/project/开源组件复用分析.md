> 目的：把视频工具（Codex 自动获客）拆成功能齿轮，逐个标注「拿来就用 ✅ / 改造 ⚠️ / 自研 🔧」，确定 MVP 开发量。
> 依据：xiaohongshu-mcp README 全文（已核实，2026-10-25）+ rednote-mcp（npm）+ 前期调研。
> 结论先行：**MVP 的采集+发布两大核心齿轮已有成熟开源实现，我们主要是"组装 + 加 UI + 加珠宝垂直逻辑"，自研部分很小。**

## 二、详细复用说明

### G1 登录/Cookie ✅（改造点：加密）
- **现成**：`check_login_status`（无参查登录）、`get_login_qrcode`（二维码登录）、`delete_cookies`；Cookie 存文件（`./data/cookies.json`）
- **视频做法**："Cookie Windows 加密保存本机、自动读取、不上传"——对应到我们：Cookie 文件存本地，不落 git；加密可用 macOS Keychain / DPAPI 级封装（security-baseline 规范），改造量小
- **注意**：README 明确"同一账号不能在多个网页端登录，会互相踢出"——我们单号单环境，符合

### G2 搜索采集 ✅（完美匹配视频功能面板）
视频面板字段 ↔ search_feeds 参数逐项对应：
| 视频面板 | search_feeds 参数 |
|---|---|
| 排序：综合/最新/收藏 | sort_by：综合/最新/最多点赞/最多评论/最多收藏（含收藏 ✅） |
| 笔记类型：全部 | note_type：不限/视频/图文 |
| 请求间隔 1000ms | 客户端侧控制（自研调用循环加间隔） |
| 结果上限 50 | 客户端侧翻页控制 |
| 搜索结果带作者/摘要 | 返回 JSON 自带 |

### G4 帖子详情 ✅（评分素材完备）
`get_feed_detail(feed_id, xsec_token)` 返回：标题/描述/图片、用户信息、**互动数据（赞/藏/分享/评论数）**、评论列表及子评论——评分需要的全部字段都有。`xsec_token` 从搜索结果里就能拿到（README 说明）。

### G5 评分数据流水线 ✅（源码核实：字段全覆盖，需两步调用）
> 源码核实：`xiaohongshu/types.go`（2026-10-25 直读 main 分支）确认字段可得性。

**评分 4 维度 ↔ 组件返回字段映射**：
| 维度 | 需要的数据 | 数据来源（字段名） |
|---|---|---|
| 点赞粉丝比 | 点赞数 ÷ 粉丝数 | 点赞=`interactInfo.likedCount`（search/详情都有）；粉丝数=`user_profile` 的 `interactions[type=fans].count` |
| 低粉权重 | 作者粉丝数 | `user_profile` → `interactions`（type="fans"） |
| 互动健康度 | 赞/藏/评/分享 | `interactInfo.likedCount / collectedCount / commentCount / sharedCount`（一条记录全有） |
| 时效性 | 发布时间 | `get_feed_detail` → `time`（int64 时间戳） |

**关键实现约束（源码确认的坑）**：
1. **`search_feeds` 卡片不含粉丝数和发布时间**（只有赞/藏/评/转）→ 评分需两步流水线：
   ```
   ① search_feeds 搜 50 条（拿互动数据）
   ② 按互动初筛候选（如前 15 条）
   ③ 对候选调 get_feed_detail（拿发布时间）+ user_profile（拿粉丝数）
   ④ 评分函数计算 → 排序标记
   ```
2. **按作者去重缓存** `user_profile`：同一作者多条笔记只查一次粉丝数（50 条结果通常只需 5-10 次主页查询）
3. 返回字段类型多为 string（如 `"likedCount":"1234"`），计算前需转 int
4. 评分是 FastAPI 壳内纯函数 `score_note()`，权重配置化（默认：点赞粉丝比>3、粉丝<500、30 天内，来源生财实战帖，见 `research/评分模型-低粉爆款.md`）

### G8 发布 ✅（超出视频工具的能力）
`publish_content(title, content, images, tags...)` 额外还支持：
- **定时发布**（schedule_at，1小时-14天）——视频工具没有，我们白赚
- **可见范围**（公开/仅自己/仅互关）——对应视频"可见范围：公开可见"
- **is_original 原创声明**——正好接我们的"辅助创作"定位
- **绑定商品**（products）——**珠宝店可绑定自家商品，这是垂直化的金矿**
- 图片支持本地路径（推荐）——对应 D6 图片策略

### 两个发布实现怎么选（齿轮来源）
| 候选 | 目标站 | 部署 | 备注 |
|---|---|---|---|
| **xiaohongshu-mcp（Go）** | xiaohongshu.com 中国站 ✅ | 预编译二进制（darwin-arm64/windows-amd64 都有）或 Docker | **首选**（我们就是中国站） |
| rednote-mcp（Node） | rednote.com 海外站 | npx 一键 | 备选（海外站，不适合国内珠宝店） |

> ⚠️ 注意：你本机若为 macOS Intel（darwin-amd64），README 说 Intel 暂不支持预编译，需源码编译或 Docker——G1 实测时确认本机架构（Apple Silicon 直接二进制；Intel 用 Docker）。

## 三、自研清单（真正的开发量）

| 自研项 | 复杂度 | 说明 |
|---|---|---|
| Web UI（采集面板 + 编辑界面） | 中 | 前端表单 + 调用 MCP HTTP API；可先用最简 HTML/JS 起步 |
| 评分引擎 | 低 | 低粉高赞公式 + 权重配置，几十行代码 |
| 调用循环（间隔/上限/翻页） | 低 | 请求间隔 1000ms、上限 50、翻页封装 |
| SQLite 表结构 | 低 | notes 表 + 配置表 |
| Cookie 加密存储 | 低 | macOS Keychain 封装（security-baseline） |

**估算：MVP 自研 ≈ 1 周（W1 采集 + W2 编辑界面 + W3 发布串联），比"从零写"省 70%+ 工作量。**

## 四、评审结论（齿轮可用性）

1. **视频工具 80% 能力 = xiaohongshu-mcp 现成工具**（搜索/详情/发布/登录），且发布能力还超出（定时/原创声明/绑商品）
2. **我们真正的增量**：① 珠宝垂直逻辑（评分侧重、商品绑定、行业模板）② 编辑 UI ③ 合规定位（原创声明 on、辅助创作话术）
3. **风险点**：xiaohongshu-mcp 基于浏览器自动化（Playwright 内核），平台改版可能失效——README 说作者稳定运行一年多无封号；回退链：rednote-mcp → XHS-Downloader+Playwright 自拼
4. **G1 验收升级**：采集 50 条 ✅ + 发布 1 条测试笔记到草稿/仅自己可见（提前消化 W3 风险）

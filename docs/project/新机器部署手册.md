## 5. 登录与 Cookie（关键）

### 5.1 开发期（有豆包/CDP 辅助）：独立 profile 自动连接

```bash
# 启动带调试端口的 Chrome（独立 profile，避免污染日常登录态）
/Applications/Google Chrome.app/Contents/MacOS/Google Chrome \
  --user-data-dir=$HOME/.codex-xhs-profile --remote-debugging-port=9223 \
  --no-first-run --no-default-browser-check
# 首次会弹「要允许远程调试吗？」——点「允许」（开发期可由 mac-system-toolkit 授权代点脚本自动点）
```

- 在 Chrome 中打开 xiaohongshu.com 并**扫码登录**（用户可协助完成，也可随时切换账号）
- 后端 `/api/refresh_cookie_from_chrome` / `/api/login_status` 从 `.codex-xhs-profile` 的 Cookie 库读取登录态
- **红线：唯一 Chrome 单窗口单 Dock 图标；绝不拆多窗口多 profile**

### 5.2 生产引导（无豆包/无 CDP 辅助，用户自助）

仓库内已内置跨平台引导脚本（`app/scripts/`），APP 界面「CDP 配置」区引导用户执行：

```bash
python3 app/scripts/setup_chrome.py [port] [profile_dir]
# port 默认 9223；profile_dir 默认 ~/.codex-xhs-profile
# 自动按平台定位 Chrome → 带参数启动 → 打开 chrome://inspect/#remote-debugging
# 用户只需在弹出的 Chrome 里点一次「允许」→ 再扫码登录即可
```

- 未找到可用 Chrome：`python3 app/scripts/pick_chrome.py`（弹系统文件对话框让用户指定）
- 用户不允许/未配置时，APP 提示并提供链接，配置完成后按钮才可用

### 5.3 Cookie 失效处理（生产闭环）

- APP 每次打开/采集前检测 Cookie 状态（`/api/login_status` / `_read_cookie_status`）
- **失效** → APP 提示 → 用户点链接打开小红书首页完成扫码 → 回 APP 点「立即读取 Chrome 登录态」（`/api/refresh_cookie_from_chrome`）→ 成功则自动关闭登录提示
- 也支持用户**手动导入 Cookie 文本**（`/api/import_cookie`，解析后校验有效性，无效拒绝）
- **跨窗口监控/自动导入不承诺**：生产环境无 CDP 时无法跨窗口自动读取，引导用户完成扫码后回 APP 点按钮是主路径

### 6.2 踩坑备忘（实测血泪）

- **crapper/mutator 覆盖对接**：两者用**裸 pytest（系统 python3）**跑测试时会读不到项目 venv/PYTHONPATH → 全部 Cov 0%。正确姿势：先用 `coverage run`（venv）生成 `.coverage` → `coverage lcov -o coverage/data/lcov.info` → crapper `--use-existing-coverage`（写 .metrics 快照）→ mutator `--use-existing-coverage`（读快照）。**变异测试前必须先 crapper**（gauntlet 硬规矩，顺序反了假 FAIL/假 PASS）。
- **变异全量耗时**：全项目 725 位点 × 全量 pytest ≈ 数小时。按模块 filter + 配对相关测试文件（`--test-command` 指定），每轮秒级；全量留给 CI 增量（mutator `--since-last-run`）。
- **敏感数据红线**：`data/chrome-profile/`、`data/cdp_config.json`、`data/cookies*.json`、`data/llm_config.json`、`data/persona.json` 均在 .gitignore（曾发生 chrome-profile 含 Cookies/Login Data 被 public 仓库跟踪，a659e0f 移出）。新机器 clone 后确认 `git status` 无这些路径。

## 8. 纪律红线（比功能更重要，避免重蹈本机覆辙）

1. **发布永远手动**：`/api/publish` 只由用户在前端手动触发；自动化任何环节都不得代发（平台 2026-03 公告点名 AI 托管发布）。
2. **唯一 Chrome 单窗口单 Dock 图标**：CDP 相关操作全程一个 Chrome 窗口；发现多窗口/多图标先清理再继续。
3. **CDP 前后清理无关 tab**：连接/使用 Chrome 前关闭不相关 tab（**绝不关闭 APP 窗口 127.0.0.1:8791 与 about:blank**），用完同样清理。
4. **路径可移植**：代码与文档一律用 `~`/`$HOME`/`os.path.expanduser`，**不写死 /Users/<用户名>**（后续换 Mac/Windows 直接跑）。
5. **频率纪律**：采集参数内置随机间隔（2-5s），勿改快；触发平台验证/频繁/风控提示立即停止、清理 tab、**不连环重试**（限流窗口靠低频单次探测确认）。
6. **Cookie 敏感**：登录态永不进 git（.gitignore 已挡 data/*.db）；仅本机界面明文展示。
7. **一切从前端驱动**：用户操作走前端按钮，后端不主动拉起浏览器/弹窗（登录弹窗由 APP 前端触发）。

## 9. 常见坑速查

| 坑 | 解决 |
|---|---|
| 全量 pytest 曾收尾挂起 | 已根治：conftest.py `_no_real_browser` autouse fixture patch 掉 `cleanup_tabs`；根因=TestClient startup 真实调浏览器（on_event 注册原始函数对象，monkeypatch 模块属性无效） |
| crapper CRAP 全 0 | lcov 位置不对——必须 `target/coverage/python/lcov.info`（crapper 只认约定路径），且 browser_client/collect_pipeline 因 omit 无 Cov 属预期 |
| cdp_config.json 被污染为 /x /y | 测试不得真实调 `/api/cdp_setup`/save_cdp_config（早期失败测试污染过，`git checkout data/cdp_config.json` 恢复） |
| Chrome「要允许远程调试吗？」弹窗 | 开发期用 mac-system-toolkit `press_allow_locked.sh` 代点（元素级 AXPress，不点坐标）；生产期引导用户手动点一次（per-profile 持久化） |
| 授权窗点不掉/时好时坏 | 代点必须串行（跨进程锁），绝不并发 osascript；只查授权 sheet、绝不遍历网页 AX 树 |
| GitHub https 慢/失败 | 走 SSH（ssh.github.com:443）；https 需代理 |
| 改代码不生效 | `pkill -9 -f "uvicorn"` 后重启（service 层无热重载） |
| 平台限流 | Chrome tab 出现 `website-login/captcha`（"请求太频繁"）= 仍限流 → 清理残留 tab、低频单次探测，绝不连环重试 |

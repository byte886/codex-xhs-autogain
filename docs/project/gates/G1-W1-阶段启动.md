## ① 目标对齐

**一句话**：搭好本地开发环境，选定并跑通小红书采集组件——实现"按关键词采集 50 条笔记、字段完整落库"。

**可量化指标**：
1. 能用"翡翠"关键词采集 ≥50 条小红书笔记
2. 每条含字段：标题 / 作者 / 内容摘要 / 图片URL / 笔记链接 / 互动数据（赞/藏/评）
3. 数据落 SQLite 本地库，可查询可导出

## ② 范围确认

**做**：
- Python/Node 开发环境检查与补齐
- Codex CLI 连通验证（订阅登录 + `codex exec` 非交互调用跑通一次）
- 采集组件三选一并落地（候选见下）
- 关键词采集 → 结构化落库 → 导出 JSON/CSV

**不做**（W2 再做）：
- 评分算法（W2 创作阶段）
- AI 生成标题/正文（W2）
- 发布模块（W3）
- 多账号/指纹浏览器（W3 视需要）
- 界面 UI（W1 用 CLI/脚本验证即可）

## ③ 验收标准（可验证清单）

| # | 验收项 | 判定 |
|---|---|---|
| 1 | `codex exec` 能通过订阅调用返回一次结果 | 命令成功，有输出 |
| 2 | 采集组件按关键词搜索返回笔记列表 | 脚本可运行 |
| 3 | "翡翠"关键词采集 ≥50 条 | 计数验证 |
| 4 | 字段完整性抽查 5 条 | 标题/作者/摘要/图URL/链接/互动 6 字段齐全 |
| 5 | 数据落 SQLite，导出 JSON 可读 | 文件存在可打开 |

## ⑤ 风险与假设

| # | 风险/假设 | 应对 |
|---|---|---|
| 1 | 逆向接口/采集可能触发小红书风控 | 单次请求间隔 ≥1000ms；小批量；Cookie 仅本机使用；先采集后分析，不发布 |
| 2 | 组件接口可能失效（平台改版） | 三选一前先各试一条；失效则换备选 |
| 3 | Codex CLI 订阅额度限制 | Plus 额度有限，W1 只验证连通性，不跑批量 |
| 4 | 假设：本机可访问小红书网页/接口（国内网络直连） | 若需代理再按 network-and-vpn 规范处理 |
| 5 | Cookie 安全 | 遵循 security-baseline：不落明文、不进 git、仅内存/加密本地 |

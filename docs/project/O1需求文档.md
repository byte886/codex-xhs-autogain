### F0 数据生命周期（搜索用完即失效）

- **搜索/采集结果不入库**：每次搜索产生的笔记/评分数据在会话内可用，刷新或下次搜索前清理（不写入长期存储）
- **长期留存仅两类**：发布成功的笔记、保存草稿的笔记（及其关联图片）
- **客户线索（F3）**：采集后的意向客户落库（clients 表），属于运营资产，长期留存
- 验收：搜索两次后数据库中无第一次搜索的笔记残留；发布/草稿数据保留

## 2. 功能需求

### F1 LLM Key 配置（门控基础）

- **配置存储**：`data/llm_config.json`（本地明文，与 cookies.json 同信任域）；字段 `llm_api_key / openai_base_url / default_model / updated_at`
- **接口**：
  - `GET /api/llm_config`：返回配置（**key 掩码**，不泄露明文）+ `configured` 状态
  - `POST /api/llm_config`：保存；key 留空时保留旧 key（前端不回传明文）
  - `POST /api/llm_test`：测试连接（GET /models），返回可用模型清单
- **协议**：OpenAI 兼容 `chat/completions` 标准接口——覆盖 OpenAI / DeepSeek / 通义 / 中转站（OneAPI/NewAPI 等）/ **Claude 官方兼容层**（base_url=api.anthropic.com/v1 + Claude key + Claude 模型名，Anthropic 官方提供 OpenAI SDK 兼容）
- **门控**：未配置 → 前端 AI 按钮灰态 + 提示；后端 AI 接口返回 400 明确拒绝
- **验收**：未配置时调用 AI 接口返回 400；配置后可测试连接；GET 不回传明文 key

### F2 AI 文稿生成（克隆内可选增强）

- 入口：发布编辑页（克隆结果页）AI 工具条
- 动作（`POST /api/ai_generate {action, note{title,desc}}`）：

| 动作 | 输出 | 系统提示词要点 |
|---|---|---|
| title_summarize | 1 个标题（≤20字） | 提炼原标题、保留爆款方向 |
| title_rewrite | 1 个新标题（≤20字） | 保留方向、加钩子/好奇/共鸣 |
| body_create | 正文 800-1200 字 | 口语化、分段、emoji、3-5 话题标签 |
| body_rewrite | 正文（语义重写） | 换表达、保留核心信息 |
| tags | 5 个话题标签 | 品类/场景/人群/痛点，中文为主 |

- 生成结果**进编辑区可继续编辑**，再走发布（**发布永远手动**，红线不变）
- 验收：5 种动作返回可直接用的文本；未配置 Key 400；生成失败（网络/Key 无效）返回明确错误

### F3 采集客户 + 意向分级（O1 核心，对齐视频形态）

- 入口：笔记卡片「采集客户」按钮（悬停卡片出现）
- 流程：真实浏览器打开原作品页 → 滚动评论区容器（.interaction-container）→ 展开全部评论 → DOM 提取评论用户
- 采集字段：昵称 / 评论原文 / **IP 属地**（平台显示的省份级）/ 时间 / uid / 主页链接（稳定身份索引，昵称重名）
- 量级建议：**单次采集上限 = 6 页 / 120 条**（视频实测安全值，避免一次滚动过深触发风控）；总量建议 200-500 条可通过**多次/多篇笔记累计**（视频形态：单篇全部列出 94 条）
- **界面形态（对齐视频 OCR）**：评论区按条列出（头像/昵称/地区/评论/时间）→ **高意向置顶分组**（"高意向：X 条，其余按回复时间最新在前"）→ 每行「去私信」按钮 → 支持导出 CSV
- **意向分级（初版：需求词命中法，双源共识）**——先排除作者回复/广告/重复/无关评论，再按需求词命中分级：

**默认需求词表（初始版本，词表可配可改）**：

| 档位 | 默认词（命中其一） | 示例 |
|---|---|---|
| 高意向 | 留联系方式：`vx` `v信` `卫星` `v ` `微信` `私我` `私信` `滴滴` `手机` `电话` `+86`；问价/购买：`多少钱` `价格` `怎么买` `哪里买` `下单` `已买` `怎么订` `预订` | "vx 私我" "多少钱" "已私信" |
| 上意向 | 问效果/方法/渠道：`怎么做` `怎么做` `怎么做的` `求教程` `求方法` `求分享` `在哪里买` `求链接`（无购买词时）`怎么用` `怎么弄` `求经验` `有推荐吗` `推荐` `怎么练` `减了多久` `怎么区分` `问下` | "怎么做的" "求教程" "求经验" |
| 中意向 | 表态互动：`想要` `求` `羡慕` `想买` `好看想` `想尝试` `我也想` `收藏了` | "求链接" "想要" "羡慕" |
| 低意向 | 其余（纯水/无自我信息） | "好看" "哈哈哈" |

- **采集中断处理（风控）**：评论区滚动过程中触发验证码/风险页 → 立即停止本任务（已采部分保留落库，不丢弃）→ 前端提示"建议停用 ≥24h，人工确认后再恢复"→ 节流闸照常生效（≥90s）；绝不自动重试

> 词表可配：用户可在配置中增删各档位词（含 VX/v/卫星等变体），默认值见上表。命中规则=命中任一档位词即入该档（低档优先于高档的判断顺序由规则引擎保证：高→上→中依次检查）。

- **属地辅助筛选**（本地生意场景）：需求词命中且属地匹配=高优先级候选
- **人工复核**：结果=候选线索清单（≠成交名单），界面保留逐条人工复核/标记
- **评论区内容侧价值**：采集结果同时回填笔记卡片"评论信号"（评论在问什么/人在意什么）——辅助判断这篇爆文为什么爆、模板是否击中目标用户（服务主目标）
- 落库：`clients` 表（uid, feed_id, nickname, comment, profile, created_at, intent, matched_word）+ 按 (uid, feed_id) upsert 去重
- **后续增强**：AI 语义分级（把评论+上下文交给 LLM 辅助识别，不自动发送）——本期词表法先行
- 验收：采集后客户入库且带 intent 标签；重复采集不产生重复记录；高意向置顶分组正确

### F4 数据聚合视图

- 聚合维度：线索总数、意向分布（**高/上/中/低档位计数**，视频"意向分 高63/上47"即档位计数）、属地分布 TOP、近 7 天产出时间线、留联系方式计数（命中留联系方式词）
- 客户明细列表：昵称/地区/意向标签/来源笔记/命中词/联系状态，支持**导出线索 CSV**（字段：昵称、主页链接、评论原文、命中词、IP 属地）
- 验收：聚合数字与明细一致；CSV 可导出且列完整

### F5 私信话术（对齐"确认发送"形态）

- **默认模板（免费）**：{昵称} 替换占位符，多条可选模板（如："你好 {昵称}，看到你在评论区问…"）
- **AI 个性化话术（Key 门控）**：基于意向用户信息（昵称/地区/意向/原评论）生成个性化开场话术
- **触达形态（多方共识红线）**：界面列出去重后的收件人+话术 → **用户人工点"确认发送"**（或跳转小红书私信入口由用户发送）；**工具不自动发送私信**（与"发布永远手动"同源；未互关用户只能发一次、主动私信有条数限制）
- 验收：模板不依赖 Key 可用；AI 话术未配置 Key 时 400；无自动发送逻辑

### F6 采集筛选条件（小红书搜索筛选接入）

- 入口：采集页信息栏（开始搜索前可选）
- 排序（filter API 验证值，谷歌双源：GetClaudeSkills + Skillselion）：

| UI 标签 | API 值 | 说明 |
|---|---|---|
| 综合（默认） | general | - |
| 最新 | time_descending | 按发布时间 |
| 最热 | popularity_descending | 按点赞 |
| 最多评论 | comment_descending | 按评论 |
| 最多收藏 | collect_descending | 按收藏 |

- 笔记类型：全部 / 视频 / 图文（API：all / video / image）
- 时间窗（若可用）：不限 / 近 1 天 / 近 1 周 / 近 1 月（视频 UI 有下拉时间筛选）
- 筛选与关键词并存：采集页先选筛选条件再开始搜索，条件进搜索 URL（search_result?keyword=..&sort=..）
- 验收：选不同排序/类型返回的笔记列表与预期一致；不选 = 综合默认

### F7 评分维度说明（卡片分数组成）

- 依据：小红书 CES 评分（多方一致：点赞×1 + 收藏×1 + 评论×4 + 转发×4 + 关注×8；收藏权重=内容价值，评论/转发=互动深度）
- 卡片右上角分数 = 本工具综合分，组成维度（初版）：

| 维度 | 权重（初版） | 说明 |
|---|---|---|
| 互动得分（CES 折算） | 60% | 赞/藏/评/转按 CES 权重归一化 |
| 爆文率（低粉高互动） | 25% | 互动量 / 粉丝数，比值越高越"低粉爆文" |
| 新鲜度 | 10% | 近 7 天发布加分 |
| 评论信号质量 | 5% | 评论在问需求（意向词命中）加分 |

- **界面呈现**：卡片分数悬浮/点击展示维度明细（雷达条或 tooltip：互动 xx 分 · 爆文率 xx 分 · 新鲜度 xx 分 · 评论信号 xx 分）
- 决策点：具体权重与是否加"作者历史互动"维度——给想法确认后再落地（决策点 D-S5）
- 验收：每张卡片分数可展开看到各维度分值与算法说明

### F8 CDP 自动化配置（Chrome 路径 / Profile 引导）

- 目的：生产环境（无 AI 窗口、只有 APP）用户自助配置 CDP，替代开发期人工授权
- 配置项：
  - **Chrome 路径**：默认按常见路径自动检测（macOS `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`；Windows `%ProgramFiles%\Google\Chrome\Application\chrome.exe` 等）；检测失败弹出**文件对话框**让用户指定；未找到可用 Chrome → APP 提示并提供链接，用户按提示配置好后按钮才可用（不强制退出）
  - **Profile 指定**：默认独立 Profile（`~/.codex-xhs-profile`）；可指定用户已登录的 Profile 目录名（如 Default / Profile 1），读取 Local State 的 profile.last_used 默认
  - **引导式配置**：优先非启动参数方式（Profile 配置文件/UI 引导），生产环境提供 macOS/Windows 双脚本（Python 带参数启动 Chrome 打开配置页）减配置难度
  - **配置状态展示**：显示当前 Chrome 路径 / Profile / 是否可用（按钮灰态→可用）
- 验收：未配置时 CDP 按钮灰态+引导提示；指定路径后可连接；双系统脚本参数化

## 3. 核心交互流程

1. **采集**：填关键词 → 开始采集（节流闸：两次任务 ≥90s）→ 后台滚动提取 → 评分排序 → 卡片列表（右上角分数）
2. **采集客户**：卡片「采集客户」→ 打开原作品页提取评论用户 → 意向分级 → 客户库更新 → 前端客户列表可看意向标签
3. **克隆+AI 增强**：卡片「克隆」→ 编辑页（原笔记载荷）→ 可选 AI 改写标题/创作正文/改写正文/提取标签 → 手动发布或存草稿
4. **数据聚合**：客户库视图展示意向分布/属地/近 7 天产出 → 导出 CSV

## 4. 关键约束（红线）

- **发布永远手动**（不自动发布）
- **平台动作极低频**（节流闸 90s + 代理纪律：只在用户明确指示时做）
- **一切从前端驱动**（后端只做能力，不主动触发平台）
- **路径可移植**（无绝对路径硬编码）
- **唯一 Chrome 单窗口**（关页保底空白页，避免反复开关）

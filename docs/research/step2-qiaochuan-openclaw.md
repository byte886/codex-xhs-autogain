## 背景
- 客户：本地生活代运营企业，5人团队服务2-3个大客户
- 痛点：手刷太累（+2实习生）、影刀RPA要自己搭流程且平台改版就废、AI编程课学会到落地鸿沟大、飞书插件被下架、第三方监控工具（千瓜/灰豚）贵且不能采集评论/笔记文案图片

## 4个监听模块（需求拆解）
1. 对标监听：定时抓对标账号新笔记+数据变化
2. 帖子存活检测：素人代发KOC笔记，检查有没有被下架（每月200+帖）
3. 评论区线索抓取：爆款笔记评论区筛真实线索
4. 数据回传飞书：飞书机器人推送到群

## 技术栈（⭐第二套可抄实现）
- **OpenClaw**（"小龙虾"）：开源AI智能体，能操作电脑、定时执行任务、Skill扩展、远程遥控（手机/飞书群/微信群召唤）
- **比特浏览器**：独立纯净网络+指纹环境，与本机系统隔离，防风控；本地接口+浏览器窗口ID（32位）
- **飞书**：多维表格做数据仓库 + 群机器人webhook推送 + 权限配置（scopes JSON）
- 小红书skill = 比特浏览器 + DOM操作方案（量小时）；量大推荐走接口方案
- 调用链路：OpenClaw(大脑) + Skill(作业指南) → 比特浏览器接口 → 小红书页面DOM操作 → 飞书

## 结果
- 3天交付，5位数变现
- 省掉2-3个实习生盯数据的活；30分钟自动跑一轮，有变化才推
- 客户学会后自己搓了4个新工具（口播文案校验/YouTube字幕翻译/招聘网站打招呼）

## ⚠️踩坑（风控核心）
1. **采集频率太高→触发平台风控**：量大的话走接口（花钱买确定性），不要走RPA，否则号会风控
2. **没挂IP→工作室IP被污染**：采集类工作流第一件事=网络环境隔离干净
3. 认知坑：纯定制=永远在接需求的外包，无壁垒；改为"带客户一起搭"（教学+交付），每服务一个行业沉淀一套打法

## 对复刻项目的技术启发
- 视频里的"Codex自动获客"底层大概率类似：本地浏览器自动化（DOM操作/接口）采集小红书 + AI改写 + 发布
- 可选的实现路径：
  a. 乔川路径1：飞书多维表+Augment编程+Playwright+比特浏览器（内容生成→排期→发布）
  b. 乔川路径2：OpenClaw+比特浏览器+飞书（采集/监听/推送）
  c. 大周路径：手机App+RPA（覆盖普通用户）
  d. 视频工具：本地Web界面+浏览器采集+AI改写+发布（127.0.0.1:8791，桌面应用形态）
- 风控底线：采集频率控制、IP隔离、账号隔离、量走接口

# 授权机制选型与薄层设计（ADR）

> 状态：已定稿（2026-10-29）｜范围：codex-zhuke 收费授权机制的基础设计
> 决策来源：谷歌调研（Cryptlex / Keylight / 行业报告）+ 生财有术 AI 问答（小术 / 亦仁）+ 项目实际情况

## 一、背景与决策

工具面向收费交付（Mac 优先、目标跨平台、珠宝玉石赛道的小红书采集/克隆/发布效率工具）。面临「在线版 vs 客户端」的防破解矛盾：

- 纯在线版：防破解最强，但成本高（全量逻辑上云+运维）、风控难控（账号集中服务端=风控雷区）；
- 纯客户端激活码：成本低但易被分享扩散。

**决策：采用「授权在线 · 执行本地」中间形态，并分档实施。**

- 业务逻辑（采集/评分/克隆/发布/LLM 可选）**全部留在用户本地**——用户自己的 Chrome、自己的账号、自己的登录态（扫码）；
- 云端只承担三件轻活：激活/续费校验、版本与配置下发、用量统计/拉黑；
- 云端与本地业务代码完全解耦，业务不上云。

## 二、方案对比（调研结论）

| 方案 | 防破解 | 成本 | 体验 | 风控适配 | 结论 |
|---|---|---|---|---|---|
| 轻量激活码 | 低（可分享扩散） | 极低 | 最流畅 | 本地执行 | 只适合起步收第一笔钱 |
| 设备绑定（机器码） | 中（不能跨设备） | 低 | 稍繁琐 | 本地执行 | 起步期够用 |
| **授权在线·执行本地** | **高（签名许可+可拉黑）** | **中（月几十元）** | **好（离线 N 天+定期联网）** | **本地执行，不背雷** | **采用** |
| 纯在线版 | 最高 | 高+运维 | 依赖网络 | 账号集中=雷区 | 不采用 |

**行业趋势佐证**：采集/爬虫类行业纯 License 授权占比从 2021 年 51.3% 降至 2025 年 19.8%，混合收费（订阅+按量+定制）升至 63.7%；爬山虎采集器（本地客户端 69 元/月）、Web Scraper（本地客户端+云端配额）均为市场验证形态。

**关键洞察（护城河定位）**：
1. 持续更新壁垒 > 代码加密：小红书接口/页面/风控规则经常变，工具必须持续更新，破解版永远落后一个版本，平台一变旧版即废；
2. 风控正确解法 = 不替用户持有账号（工具只做效率放大，不代持账号池）；
3. 护城河放在「持续更新 + 云端素材/模板库 + 社群服务」，而非加密。

## 三、分档实施

| 档位 | 模式 | 何时启用 | 说明 |
|---|---|---|---|
| 0 | `free` | 现在（调试/朋友分享期） | `check_license` 恒放行，零门槛 |
| 1 | `activation` | 第一批付费 | 激活码+机器码绑定，0 服务端成本，杜绝批量分享 |
| 2 | `server` | 用户规模起来 | RSA 签名许可（服务端签发、客户端公钥验签）+ 定期联网校验（离线 3–7 天缓冲）+ 拉黑/续费/设备数管理 |

档位切换只改 `license.py` 内部实现，其余代码零改动。

## 四、薄层设计（现在就要定死的 4 件事）

1. **接口形状**：`license.check_license(feature) -> (ok, reason, detail)`，所有业务入口（启动、采集、克隆、发布、LLM、前端路由守卫）统一过它；`free` 模式恒放行。
2. **feature 清单**：`collect / clone / publish / llm`（前端展示与后端校验共用同一套；免费试用/付费档位以后映射到同一清单）。
3. **机器码算法**：跨平台稳定指纹（Mac/Windows），**发布后换算法 = 已发激活码全废**，故必须先定。
4. **License 文件 schema**：版本化（`schema_version`），预留 RSA 签名字段（现在为空，未来填），避免迁移数据。

## 六、验收标准（基础层）

- [ ] `free` 模式下所有功能不受任何影响（调试/分享无感）
- [ ] 所有业务入口均经过 `check_license`（代码审查可见）
- [ ] feature 清单前后端共用一份定义
- [ ] 机器码跨 Mac/Windows 稳定（同一机器多次运行一致）
- [ ] license.json 结构版本化，预留签名字段

## 七、明确不做什么（当前阶段）

- 不建授权服务端（等第一批付费用户再建，独立小 HTTP 服务，与本地代码解耦）
- 不做重壳加密/反调试（投入大、维护累、收益低）
- 不把业务逻辑搬上云（成本+封号+运维三座山）
